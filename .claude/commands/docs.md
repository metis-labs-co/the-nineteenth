## Documentation Requirements

### For Components
Generate documentation including:
- Purpose and use cases
- Props interface with descriptions
- Usage examples (basic and advanced)
- Styling customization options
- Accessibility features
- Known limitations

### For Routes
Generate documentation including:
- Route purpose and functionality
- URL parameters and query strings
- Required authentication/permissions
- Loader data structure
- Action intents and form fields
- Error handling behavior
- Example requests/responses

### For Features
Generate documentation including:
- Feature overview
- User flows
- Database schema
- API endpoints (if any)
- Components used
- Configuration options
- Testing approach

### For APIs
Generate documentation including:
- Endpoint URL and method
- Authentication requirements
- Request parameters/body schema
- Response schema (success and error)
- Example requests (curl, fetch, etc.)
- Rate limiting
- Common errors

## Documentation Format
Use Markdown with code examples. Include:
- Clear headings
- Code blocks with syntax highlighting
- Tables for parameters
- Examples that can be copy-pasted
